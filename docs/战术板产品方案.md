# 排球阵型板 · 产品方案 v0.2

> v0.2 变更：砍掉关键帧录制、时间轴、回放、GIF/MP4 导出。
> 定位从「战术动画模拟」改为**静态站位编辑**——进入模式，手指把 6 个角色拖到防守位置，松手即保存。
> v0.1 里的对象注册表、导出器注册、事件总线一并删除——只有 6 个圆点的时候上这套抽象，等于给自己收框架税。

---

## 1. 一句话

一个模式：进去，把 6 个角色拖到你要的防守位置，松手自动吸附自动保存，退出再进来还在。

---

## 2. 角色位（固定 6 个）

| 角色 | 说明 |
|---|---|
| 主攻1 / 主攻2 | 左边和右边的两点攻 |
| 副攻 | 网前中路 |
| 接应 | 网前另一侧 |
| 二传 | 组织点 |
| 自由人 | 后排防守核心 |

- **绑定的是位置角色，不是具体队员**——换人不换战术，一套站位能一直用；
- 这 6 个正好是「自由人在场」时的组合（自由人替换后排副攻），所以你只列 1 个副攻是对的；
- 本版不支持增删角色；以后要加「替补」或换运动项目，再走配置化。

---

## 3. 交互规范

### 3.1 拖动

- 触控与鼠标同一套 Pointer Events，平板手指、电脑鼠标都能拖；
- 抓取半径 ≥ 44px（手指比圆点大，按圆心命中会频繁抓空）；
- 抓起瞬间：放大 1.14、虚线光环、原位留 28% 透明度的幽灵；
- 拖动中浮出坐标胶囊：`x 5.25m · 距网 4.50m`；
- 松手吸附 **0.25m**，140ms 回弹动画；
- 双击队员归位；拖动结束自动保存，不需要保存按钮。

### 3.2 一个刻意的减法：不做画布缩放和平移

半场 9×9m 正好一屏铺满，做了缩放只会多一个和拖动抢事件的手势源。
**本版没有工具栏**——因为只有「拖动」这一种操作，加模式切换是多余的心智负担。

### 3.3 坐标系

- 原点在网正中，`x` 0–9 从左到右，`y` 0–9 从网到端线，单位米；
- 边界内缩 0.30m，保证圆点不会被切在边线上；
- 3m 进攻线固定在 `y = 3`，作为视觉基准。

---

## 4. 预设与保存

- 内置 3 套：「默认站位」「退守」「网前拦防」，一键套用；
- 拖动任意一个角色后，预设标记自动取消，变成自定义；
- 数据存本机 localStorage，刷新、关浏览器都不丢；
- 「恢复默认」回到默认站位。

---

## 5. 数据模型

```ts
type RoleId = 'oh1' | 'oh2' | 'mb' | 'opp' | 's' | 'lib';

interface Formation {
  version: 1;
  preset: 'base' | 'deep' | 'block' | 'custom';
  pos: Record<RoleId, { x: number; y: number }>;   // 米
}
```

**为什么要留 `version`**：以后加「多套阵型」「轮转顺序」「跑位动画」都要改结构，一个版本号能让老数据平滑升级，不用写一次性迁移脚本。

**为什么不用数组存角色**：角色固定 6 个，用 `Record<RoleId, ...>` 编译期就能防止漏写、错写；数组要多一层查找和校验。

## 6. 扩展预留（只留真正会用到的）

| 未来功能 | 怎么长出来 | 现在要做的准备 |
|---|---|---|
| 多套阵型 / 战术库 | `formations: Formation[]` + 名称 + 标签 | 结构已是对象，包一层数组即可 |
| 阵型命名与切换 | 顶部加下拉 | 无 |
| 导出 PNG 发群里 | html2canvas 或 SVG 序列化 | 无（DOM 结构已是矢量友好的） |
| 跑位动画 | `frames: [{ t, pos }]`，第 0 帧 = 现在的 `pos` | **零迁移**，现在的数据天然是第一帧 |
| 其他运动 / 轮次 | 角色表配置化 | 现在硬编码 6 个，等第二种需求再抽 |
| 与训练 / 比赛关联 | 训练记录挂 `formationId` | 需要主系统的数据层 |

**这条要记住**：先有第二个用例，再做抽象。现在只有 6 个圆点和一个拖动，任何「注册表」「插件系统」都是负债。

## 7. 与现有系统的关系

- 入口：侧栏新增「阵型」，和人员 / 考勤 / 成长并列；
- 不依赖队员数据——没有队员也能用，帮外校看站位、临时讲两句都行；
- 后续：某次训练可以挂一套阵型，点进去直接看。

## 9. 设备策略

- **触控优先，鼠标可用**：Pointer Events 一套代码通吃；
- 震动：只有安卓 Chrome 支持，iOS Safari 没有——**降级为视觉脉冲**，不做成必要条件；
- Pencil：只有 iPad 有，本版也不需要压感——手指拖动用不上笔；
- 结论：**两个都不作为依赖**，安卓平板、iPad、电脑浏览器表现一致。
