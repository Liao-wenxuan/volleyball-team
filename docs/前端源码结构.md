# 前端源码分片结构

> app.js 有 5000 行、全在一个 IIFE 里，靠命名约定而非模块边界维持。
> 这份文档说明拆分后的结构、为什么这么拆、以及**日常怎么改代码**。

---

## 1. 一句话

**源码分片在 `src/`，构建产物仍是单个 `app.js`。**

```
src/*.js  ──(build.mjs 拼接)──→  app.js  ──(再内联进 HTML)──→  信工院排球队管理系统.html
```

`app.js` 是**产物**，不是源码。改代码要改 `src/` 下的分片。

---

## 2. 为什么不直接改成 ESM

两条硬约束决定了不能直接换模块系统：

1. **测试机制**：`tests/load-app.mjs` 用 `node:vm` 加载**单个** `app.js` 文件，
   靠文件末尾 `typeof module !== 'undefined'` 的导出钩子把纯函数交给 `node:test`。
   这样测的是生产源码本身，不维护副本、不引打包链。
2. **单文件分发**：`build.mjs` 把所有 CSS/JS/按需模块/loader 图片内联进一个 HTML，
   用户双击就能离线用。产物形态一变，这套内联逻辑要重写。

保持 `app.js` 仍是「一个 IIFE 的单文件」，上面两件事都不用动。
**维护**这件事从「5000 行一个文件」变成「按领域分的一堆文件」——这才是这次改动的目的。

## 4. 日常怎么改

```bash
# 1. 改 src/ 下的分片
vim src/players.js

# 2. 构建（自动拼接成 app.js + 内联单文件 HTML）
npm run build

# 3. 跑全部测试
npm run test:all
```

**不要直接改 `app.js`** —— 下次 `npm run build` 会覆盖它。

`npm run build` 的输出里有一行守卫：

```
guard: app.js 与 HEAD 版本逐字节一致 ✅
```

首次拆分后这行是 ✅。之后你改了分片，这行会显示差异行数——**这是正常的**
（产物变了、HEAD 里的 app.js 还没更新）。提交时把 `app.js` 一起提交即可。

---

## 5. 三条不能违反的规则

### 5.1 分片顺序 = 原文件里的出现顺序，不能重排

最初尝试按「领域」重排分片（core → theme → players…），直接炸了：

```
ReferenceError: Cannot access 'FX_ROLES' before initialization
    at blankFormation (app.js:533:5)
    at blankDB (app.js:143:146)
    at loadDB (app.js:284:14)
```

原因：JS 的 `const`/`let` 有 **TDZ（暂时性死区）**——声明之前引用会**抛错**，
而不是像 `var` 那样拿到 `undefined`。`blankDB()` 在模块加载期就会调用
`blankFormation()`，后者依赖 theme 里的 `FX_ROLES` 常量。
把 theme 排到 core 后面，`blankDB()` 执行时 `FX_ROLES` 还没初始化。

领域只决定「哪些**相邻**区块归到一个文件」，不决定文件之间的先后。

### 5.2 切分的源必须是 git 里的原始 app.js

`app.js` 是构建产物，会被 `build.mjs` 覆盖。所以 `tools/split-app.mjs` 用
`git show HEAD:app.js` 取源，**不读磁盘上的 app.js**。

理由：调试期间 build 留下的产物里可能已有多余空行，直接读它当源，
偏差会在「切分 → 构建 → 再切分」之间**累积**（我踩过：一次比一次多几个空行，
最后产物比原文多 25 行，且很难看出是哪一步引入的）。

拿不到 git 版本时脚本**直接报错退出**，不做降级——宁可什么都不做，
也不能拿被污染的产物当源。

### 5.3 段落合并必须「紧邻」

合并同一领域的相邻区块时，条件是「同归属 **且** 上一段的 end 就是本段的 start」。

只判「同归属」会出事：core 的三块中间夹着 theme 的两块，一路合并会让
core 的区间跨越 theme 的内容，**同一段代码出现两次**，产物多出 25 行。

## 6. 重新切分

如果 app.js 的结构变了（比如新增了大区块），重新切分：

```bash
# 先看看切分计划，不写文件
node tools/split-app.mjs --dry

# 看看每个区块的归属和行区间
node tools/split-app.mjs --dry --verbose

# 实际切分
node tools/split-app.mjs

# 构建 + 守卫校验
npm run build
```

**注意**：`split-app.mjs` 的源是 `git show HEAD:app.js`。
所以流程是：**先提交 app.js 的改动 → 再切分 → 再构建 → 再提交分片**。

---

## 7. 校验方式

拆分这个动作的正确性不靠肉眼 diff，靠三道关：

1. **字节级守卫**（`build.mjs`）：拼接产物 vs `git show HEAD:app.js`，
   逐字节比较，完全一致才输出 ✅。
2. **纯函数单测**（`npm run test:pure`）：54 条，用 vm 加载真实 `app.js`。
   测的是拼接后的产物，功能变了这里立刻红。
3. **端到端**（`npm run e2e`）：5 条，真浏览器 → 真前端 → 真后端 → 真 SQLite，
   覆盖登录、考勤、阵型拖拽、主题一致性、跨队残留。

拆分完成时三项实测：**199→207 后端单测、54/54 纯函数、5/5 e2e，全绿；
产物与原 app.js 逐字节一致；单文件 HTML 762.3 KB（与拆分前一致）。**
